# Radio World Auto

Нативное Android-приложение для прослушивания интернет-радиостанций в автомобиле, на телефоне и планшете. Реализовано на Kotlin с XML Views и Media3/ExoPlayer.

## Возможности приложения

- **Три адаптивных варианта интерфейса:** автомобильный экран для профиля 1920×720 и responsive-интерфейс для телефонов и планшетов в портретной и альбомной ориентации.
- **Радиокаталог:** станции по странам, поиск, избранное и недавно прослушанные станции.
- **Поиск по мере ввода:** результаты обновляются во время набора текста; поддерживается экранная клавиатура.
- **Управление воспроизведением:** Play/Pause, переключение станций, случайный выбор станции и управление через Android MediaSession.
- **Информация о текущем эфире:** отображение доступных названия трека и исполнителя; при отсутствии метаданных используется название станции.
- **Устойчивость воспроизведения:** сохранение выбранной станции, локальный кэш каталога и логотипов, повторное подключение и переход к альтернативному адресу потока, если он есть.
- **Настройки:** тема (системная, светлая или тёмная), язык интерфейса (русский/английский), режим «не выключать экран», ручная проверка обновления каталога и информация о приложении.
- **Интерфейс проигрывателя:** мини-плеер, избранное и фон текущего проигрывателя с визуальным оформлением станции.

Автомобильный интерфейс и мобильный/планшетный интерфейс разделены, чтобы точечные изменения одного варианта не ломали другой.

## Каталог радиостанций

Установленное приложение загружает опубликованные данные каталога непосредственно из **GitHub Raw**. Для работы Android-приложения отдельный сервер не требуется.

Workflow **Catalog snapshot**:
- запускается по расписанию каждые 6 часов и вручную через GitHub Actions;
- собирает данные из Radio Browser, IPRD и курируемого списка;
- нормализует и объединяет записи, удаляет дубликаты, проверяет потоки и применяет фильтры;
- ограничивает публикацию максимум 500 станциями на страну.

Опубликованные файлы находятся в ветке **catalog-data**:
- `data/stations.json` — основной каталог приложения;
- `data/catalog-manifest.json` — версия каталога, статистика и ссылки на обновление;
- `data/catalog-delta.json` — изменения относительно предыдущей версии;
- `data/radio.db` — SQLite-база для служебных задач публикации;
- `debug/` — статическая страница и диагностические данные каталога.

Ветка `catalog-data` содержит генерируемую публикацию, а не исходный код приложения. Она создаётся как snapshot и обновляется workflow; её не следует сливать с `main`.

### Обновление каталога на устройстве

1. При первой загрузке приложение получает полный каталог.
2. При последующей синхронизации приложение проверяет manifest.
3. Если версия изменилась и локальная версия подходит, применяется delta.
4. Если delta отсутствует или её нельзя безопасно применить, загружается полный каталог.
5. Каталог хранится локально, поэтому при временной недоступности GitHub уже сохранённые станции остаются доступны.

## Разработка и проверки

**Исходная ветка приложения: `main`.** Изменения вносятся через pull request; не следует использовать старые feature/refactor-ветки как источник актуального кода.

Основные workflow GitHub Actions:

- **Android unit tests** — быстрые unit-тесты Android-кода;
- **API and catalog metadata tests** — тесты инструментов каталога, importer и метаданных;
- **Collector tests** — тесты сборщика и нормализации каталога;
- **Android Release APK** — ручная release-сборка, тесты, lint, подпись и публикация APK как GitHub Actions artifact;
- **Catalog snapshot** — сборка, проверка и публикация каталога;
- **Catalog health check** — ручная проверка опубликованного каталога.

Для изменений в `main` обязательны проверки **Android unit tests**, **API and catalog metadata tests** и **Collector tests**. Изменения каталога не должны сами по себе запускать Android Release APK.

APK публикуется как один из GitHub Actions artifacts: **`radio-world-auto-release`** при использовании постоянного ключа подписи или **`radio-world-auto-test-build`** при временной тестовой подписи. Отчёт lint публикуется отдельно как **`android-lint-report`**. Для установки поверх существующей версии нужен APK, подписанный постоянным ключом приложения; временно подписанная тестовая сборка для этого не подходит.

## Структура репозитория

- `android/` — Android-приложение, ресурсы и unit-тесты;
- `collector/` — сбор и обработка источников радиостанций;
- `tools/` — формирование manifest/delta и проверка публикации;
- `api/` — importer и инструменты каталога, используемые в процессе публикации;
- `docs/` — документация по архитектуре, проверкам и аудиту;
- `.github/workflows/` — сборки, тесты и публикация каталога.

## Текущий статус

Автоматические проверки обязательных PR проходят; публикация каталога и GitHub Pages проверена end-to-end. Финальная проверка на реальных устройствах (телефон, планшет и автомобильный экран/Headunit Reloaded, если доступен) остаётся отдельным этапом. Это не означает, что известна неисправность: нужно подтвердить воспроизведение, управление, восстановление и обновление установленной версии на целевых устройствах.
