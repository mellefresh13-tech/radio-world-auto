# Сопровождение проекта

Обновлено: 2026-11-10.

## Текущие приоритеты

1. Поддерживать стабильность воспроизведения на автомобильных и мобильных устройствах.
2. Сохранять надёжность обновления и отдельной публикации каталога.
3. Поддерживать актуальность Android, Python и GitHub Actions зависимостей.
4. Выполнять обязательные CI-проверки для каждого изменения и ручную проверку release APK перед распространением.
5. Поддерживать точность документации, политики конфиденциальности и Google Play Data safety disclosures относительно фактических Firebase SDK и событий.

## Правила изменений

- Новые функции добавляются отдельными небольшими задачами.
- Исправления не должны включать несвязанные изменения интерфейса, каталога или CI.
- Изменения, затрагивающие воспроизведение, проверяются на целевых устройствах.
- Release APK создаётся вручную; обычные изменения `main` не должны запускать лишние релизные сборки.
- `catalog-data` поддерживается workflow и не используется как ветка разработки приложения.
- Изменения в аналитике, диагностике или сторонних SDK сопровождаются проверкой политики конфиденциальности и Data safety.

## Планирование

Новые продуктовые функции, платформенная интеграция и изменение схемы публикации не считаются согласованными только потому, что упомянуты в старых заметках или обсуждениях. Их следует добавлять в план после отдельного решения владельца проекта.

Этот документ содержит действующие направления сопровождения, а не историю завершённых экспериментов и отклонённых решений.
