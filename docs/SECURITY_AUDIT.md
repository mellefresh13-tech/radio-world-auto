# Заметки по безопасности

Обновлено: 2026-11-10.

Этот документ фиксирует меры и ограничения, видимые в репозитории. Он не является независимым penetration test или формальной сертификацией безопасности.

## Репозиторий и CI

- Секреты подписи Android хранятся в GitHub Environment `android-release-signing`, а не в исходном коде.
- Release workflow проверяет сертификат постоянной подписи по отдельно заданному SHA-256 fingerprint.
- Для задач CI следует использовать минимальные необходимые разрешения GitHub token.
- Публикация каталога отделена от подготовки данных и выполняется отдельным workflow.
- Зависимости обновляются через pull request и обязательные CI-проверки.

## Android и Firebase

- В Android manifest запрашиваются сетевые разрешения и разрешения, необходимые для фонового воспроизведения и уведомлений; разрешения на точное местоположение и контакты не запрашиваются.
- Firebase Analytics и Crashlytics подключены в Android-приложении. Их сбор включён в текущей конфигурации; отдельного пользовательского переключателя в приложении нет.
- Для Analytics отключены Advertising ID collection и ad-personalization signals. Это не отключает саму аналитику и не означает отсутствия всех автоматически собираемых технических данных SDK.
- В Analytics передаются события использования приложения, идентификаторы и публичные метаданные станций, тип интерфейса, язык/тема, а также отфильтрованный текст поискового запроса при прохождении встроенных ограничений.
- Crashlytics автоматически отправляет диагностические сведения о фатальных сбоях и поддерживаемых ANR. В качестве custom keys приложение задаёт тип интерфейса и версию приложения.
- Отдельный локальный файл `last_crash.txt` используется для отображения/копирования ошибки на следующем запуске и исключён из Android backup и device transfer.
- Публичная политика конфиденциальности и Google Play Data safety должны соответствовать фактическому поведению обоих Firebase SDK.

Подробности о событиях и передаваемых параметрах находятся в [ANALYTICS_EVENTS.md](ANALYTICS_EVENTS.md) и [FIREBASE_ANALYTICS.md](FIREBASE_ANALYTICS.md).

## Каталог и внешние данные

- Каталог формируется из внешних источников; его содержимое может быть неполным или устаревшим.
- Успешная проверка потока не гарантирует его постоянную доступность.
- Публикуемые данные проходят структурные проверки до публикации.
- Ветка `catalog-data` содержит сгенерированные данные и материалы публикации.

## Release signing

Используйте только постоянный ключ, хранящийся в защищённом GitHub Environment. Перед выпуском проверьте совпадение fingerprint с доверенным сертификатом. Подробная процедура описана в [RELEASE_SIGNING_FINGERPRINT.md](RELEASE_SIGNING_FINGERPRINT.md).

## Ограничения и дальнейшая проверка

- Проверить соответствие Google Play Data safety формы фактическим данным Firebase перед отправкой новой версии на проверку.
- Проверить применимые требования согласия/уведомления для регионов распространения; в текущем приложении отдельного in-app consent/opt-out интерфейса нет.
- Периодически проверять разрешения Android, зависимости, Firebase SDK и публичную политику конфиденциальности.
- CI и описанные меры не заменяют ручное и независимое тестирование безопасности.

Не публикуйте в документации секреты, приватные ключи, пароли или сведения, упрощающие эксплуатацию конкретных уязвимостей.
