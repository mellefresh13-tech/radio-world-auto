# Заметки по безопасности

Обновлено: 2026-11-04.

Этот документ описывает текущие общие меры безопасности проекта. Он не является результатом независимого penetration test или формальной сертификацией безопасности.

## Репозиторий и CI

- Секреты подписи Android хранятся в GitHub Environment `android-release-signing`, а не в исходном коде.
- Release workflow проверяет сертификат постоянной подписи по отдельно заданному SHA-256 fingerprint.
- Задачи, которым не требуется запись в репозиторий, используют минимальные разрешения GitHub token.
- Публикация каталога разделяет этап подготовки данных и этап публикации с правами записи.
- Зависимости обновляются через pull request и обязательные CI-проверки.

## Android

- Секреты подписи не должны включаться в APK, исходный код или документацию.
- Сетевые данные и сторонние URL должны рассматриваться как недоверенный ввод.
- Разрешения приложения должны оставаться ограниченными необходимыми функциями.
- Изменения MediaSession и внешнего управления требуют проверки совместимости с системными медиаконтроллерами.

## Каталог и внешние данные

- Каталог формируется из внешних источников; его содержимое может быть неполным или устаревшим.
- Успешная проверка потока не гарантирует его постоянную доступность.
- Публикуемые данные должны проходить структурные проверки до публикации.
- Ветка `catalog-data` содержит только сгенерированные данные и материалы публикации.

## Release signing

Используйте только постоянный ключ, хранящийся в защищённом GitHub Environment. Перед выпуском проверьте, что fingerprint совпадает с доверенным сертификатом. Подробная процедура описана в [RELEASE_SIGNING_FINGERPRINT.md](RELEASE_SIGNING_FINGERPRINT.md).

## Ограничения

CI-проверки и описанные меры снижают риск регрессий, но не заменяют периодический аудит зависимостей, проверку разрешений Android и независимое тестирование безопасности. Не публикуйте в документации секреты, приватные ключи, пароли или подробности, которые облегчают эксплуатацию конкретных уязвимостей.
